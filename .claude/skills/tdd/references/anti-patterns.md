## AP.1 Red フェーズのアンチパターン

| # | アンチパターン | 説明 | 検出方法 |
|---|---------------|------|---------|
| R-1 | 実装ファースト | テスト前に実装を書く | 直前のコミット差分が実装ファイルのみ |
| R-2 | 成功テスト先行 | 必ず通るテストを Red と称する | 1 回目実行で失敗が確認されない |
| R-3 | 失敗確認スキップ | テストを書いて即座に Green に進む | テスト実行ログが残らない |
| R-4 | 多機能テスト | 1 テストケースで複数振る舞いを検証 | 1 テスト内に複数 Act がある |
| R-5 | コンパイルエラー Red | コンパイルエラーを「失敗」と誤認 | エラーが Assertion 由来でない |
| R-6 | 期待値置き去り | Assert 文がないテストを書く | テストに `assert` / `expect` 等が含まれない |
| R-7 | Red 観測欠落（過剰実装による Red バイパス） | テスト書く前に対象実装が完成しており、初回実行で Green になる（前 step S-4 の G-1 過剰実装が伝播した結果） | 1 回目実行で当該テストが Pass する。`grep -rn "対象シンボル" 対象ディレクトリ` で対象実装の事前存在を検出 |

## AP.2 Green フェーズのアンチパターン

| # | アンチパターン | 説明 | 検出方法 |
|---|---------------|------|---------|
| G-1 | 過剰実装 | 当該テスト以外の振る舞いを先取り実装 | 直前テストで検証されない分岐が実装される |
| G-2 | 設計最適化 | Green 段階で抽象化・パターン適用 | リファクタリングが Green に混入 |
| G-3 | 並行機能追加 | 別機能を同時に実装 | 当該テスト範囲外のクラス・関数が変更される |
| G-4 | 全テスト未実行 | 当該テストのみ実行して進む | 既存テストの破壊が見過ごされる |
| G-5 | テスト改変 | テストを書き換えて通す | テストファイルが Green 段階で変更される |
| G-6 | カバレッジ無視 | Green 完了時にカバレッジ低下 | カバレッジレポートが Green 直前より低下 |

## AP.3 Refactor フェーズのアンチパターン

| # | アンチパターン | 説明 | 検出方法 |
|---|---------------|------|---------|
| F-1 | 新規ロジック追加 | リファクタ中に振る舞いを追加 | テストが追加されていないのに分岐が増える |
| F-2 | テスト未実行 | リファクタ後にテストを実行しない | リファクタ完了報告にテスト結果が無い |
| F-3 | 赤のままリファクタ | テストが失敗している状態でリファクタ | リファクタ前のテスト結果が Red |
| F-4 | テストコード変更 | リファクタ対象が実装ではなくテスト | テストファイルが Refactor 段階で改変 |
| F-5 | 過剰抽象化 | YAGNI 違反の汎用化・一般化 | 当該テストで使われない API が追加される |
| F-6 | 全置き換え | 動作中コードを大幅に書き換え | 差分が 30% を超える |

## AP.4 横断アンチパターン（サイクル全体）

| # | アンチパターン | 説明 | 検出方法 |
|---|---------------|------|---------|
| X-1 | カウボーイ TDD | テスト後付け（Test-After） | 実装コミットの後にテストコミットがある |
| X-2 | 自己満足テスト | プロダクションコードの行をなぞるだけ | テストケース名が実装メソッド名と 1:1 対応 |
| X-3 | 統合テスト混入 | 単体テストに DB / 外部 API が含まれる | F.I.R.S.T の Fast / Independent 違反 |
| X-4 | テスト負債放置 | 失敗テストを `skip` / `pending` に変更 | スキップ理由がコメントに無い |
| X-5 | カバレッジ偽装 | 計測対象から除外して 100% 達成 | カバレッジ設定にホワイトリスト除外がある |
| X-6 | サイクル省略 | Red を飛ばして Green / Refactor を直接実施 | step S-3 の出力テンプレートに記入が無い |
