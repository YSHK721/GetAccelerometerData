## TD.1 同値分割テスト設計

入力空間を「同じ振る舞いを期待するクラス」に分割し、各クラスから 1 つずつテストケースを選定する。

| 入力種別 | 同値クラス例 | テストケース最小数 |
|---------|-------------|----------------|
| 整数範囲 1-100 | 無効（≤0）/ 有効（1-100）/ 無効（>100） | 3 |
| 文字列長 1-50 | 空 / 短い / 中間 / 長い / 超過 | 5 |
| 列挙値 | 各列挙値 + 範囲外 | N+1 |

## TD.2 境界値テスト設計

同値クラスの境界に欠陥が集中する経験則に基づき、以下を必ずテストする：

| 境界 | テスト対象 |
|------|----------|
| 下限 | 下限値 / 下限値 -1 |
| 上限 | 上限値 / 上限値 +1 |
| 0 / 空 | 空配列 / 空文字 / null / 未定義 |
| オーバーフロー | 型最大値 / 最大値 +1 |
| 配列境界 | 先頭 / 末尾 / 単一要素 |

## TD.3 デシジョンテーブル

複数条件の組み合わせで振る舞いが変わる場合、全組み合わせを表化してテストケースを導出する。

| 条件 1 | 条件 2 | 条件 3 | 期待結果 | テストケース ID |
|-------|-------|-------|---------|---------------|
| T | T | T | A | TC-001 |
| T | T | F | B | TC-002 |
| ... | ... | ... | ... | ... |

組み合わせ爆発時はペアワイズ法で代替する。

## TD.4 状態遷移テスト

オブジェクトが状態を持つ場合、状態遷移図から以下を導出する：

| テスト種別 | 内容 |
|-----------|------|
| 全状態到達 | 各状態に到達するケース |
| 全遷移実行 | 各遷移を実行するケース |
| 不正遷移拒否 | 許可されない遷移を試みるケース |
| 自己ループ | 同じ状態に戻る遷移ケース |

## TD.5 AAA 構造の細則

### Arrange

- テスト対象の前提条件を最小に絞る
- グローバル状態を使用しない（並行実行可能性確保）
- ビルダーパターン / Object Mother で繰り返しを排除する

### Act

- 1 テストケースに 1 Act のみ
- 戻り値・例外を変数に束縛して Assert に渡す

### Assert

- 期待値 / 実測値の順序をテストフレームワークの規約に統一
- 1 Assert 1 概念（複数の assertion を 1 ケースに含めても可。ただし論理的に 1 つの振る舞いを検証する場合に限る）
- メッセージ付き Assert で失敗時の手掛かりを残す

## TD.6 モック / スタブ / スパイ / フェイク / ダミー

| 種別 | 役割 | 使用場面 |
|------|------|---------|
| ダミー | 引数を埋めるだけ。呼び出されない | コンストラクタ引数の埋め草 |
| スタブ | 固定値を返す | 外部依存の戻り値固定 |
| スパイ | 呼び出し履歴を記録 | 副作用の発生検証 |
| モック | 期待呼び出しを事前定義し検証 | 厳密な相互作用検証 |
| フェイク | 簡易実装で本物を代替 | インメモリ DB / 偽外部サービス |

選定原則：
- 単体テスト = スタブ / フェイク優先
- 相互作用が仕様の核心 = モック使用
- 過剰モック化は実装詳細とテストの結合を生むため回避
