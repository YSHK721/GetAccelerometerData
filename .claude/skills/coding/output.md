## 出力時の遵守事項

- 10 項目をすべて記入する。空欄は許容しない（該当なしの場合は「該当なし」と明記）
- 章番号・章タイトル・順序はテンプレート通りに保持する（SKILL.md §4「出力順序固定」ルール準拠）
- ID 体系を統一：アクター `A-N` / クラス `C-N` / 抽象 `AB-N` / インターフェース `I-N` / 判断 `D-N`
- §3〜§7 では関連する ID（A-N / C-N / AB-N / I-N）を相互参照する
- §3〜§7 のすべての設計判断について「採用理由」「代替案」「棄却理由」の 3 列を空欄なく記入する（SKILL.md §4「根拠必須」「代替案必須」ルール準拠）
- §4 抽象化点には「現存する変更要求の根拠（出典必須）」を必ず記入する。出典なき抽象化は採用しない（SKILL.md §4「YAGNI 遵守」ルール準拠）
- §5.1 の Pre / Post / Inv は基底型ごとに明示する。派生型の §5.2 は契約遵守を ✅ または違反内容で記述する
- §7.1 依存方向図は Mermaid `graph LR` ブロックで記述し、実線（`-->`）を「依存」、点線（`-.-`）を「実装」として区別する
- §10 未解決事項は必ず「仮説：」プレフィックスを付し、観察可能事実と区別する（SKILL.md §4「推測禁止」ルール準拠）
- レイヤー間構造設計（クリーンアーキテクチャ）・基本/内部設計書文書化（system-design）への踏み込みは禁止する。該当する事項は §1 除外事項に明記し、対応スキルへの委譲を提案する（SKILL.md §4「スコープ分離」ルール準拠）
- 設計対象は §1 で明示された範囲のみとする（SKILL.md §4「範囲限定」ルール準拠）
- 主観・感想・印象（「綺麗な設計」「良いインターフェース」「読みやすい」等）は出力しない（SKILL.md §4「主観禁止」ルール準拠）
- 曖昧表現（「適切に」「効率的に」「一般的に」「可能な限り」「柔軟に」「自然に」等）は出力しない（SKILL.md §4「曖昧表現禁止」ルール準拠）
